Install and set up Git

Install Git, tell it who you are, and connect your computer to GitHub so you can push your work.

Learning goals

  • Install Git on Linux, macOS or Windows
  • Set your name and email so every commit shows who made it
  • Make main the default branch name and pick an editor
  • Understand the three config levels: system, global and local
  • Connect your computer to GitHub with gh auth login or an SSH key

The idea

You install Git once per computer. Then you set it up once, and those settings apply to every project on that computer. Setup has two parts: telling Git who you are, and proving to GitHub that you are allowed to push.

Your identity is stamped on every commit

Every commit records an author name and email. Git takes them from your settings, user.name and user.email. GitHub uses the email to link a commit to your account and show your profile picture next to it.

commit 5359e52
Author: Your Name <you@example.com>   ◄ from user.name + user.email
Date:   Sat Nov 7 10:52:00 2026

    fix(js): load module registry fresh

Want to keep your real email private? On GitHub, go to Settings → Emails and turn on "Keep my email addresses private". GitHub then gives you an address like 12345678+username@users.noreply.github.com. Use that as your user.email.

Three levels of settings

Git reads settings from three places. If the same setting is in more than one place, the closest one wins:

LevelApplies toSaved in
--systemEvery user on this computer/etc/gitconfig
--globalYou, in every repo~/.gitconfig
--localOne repo only (this beats the others).git/config inside that repo

Most of the time you only use --global. Use --local when one project needs something different, like your work email in a company repo.

Proving who you are to GitHub

Anyone can read a public repo, but only allowed people can push to it. GitHub stopped accepting account passwords for git push in 2021. You need one of these instead:

HTTPS + tokenSSH key
Repo URL looks likehttps://github.com/user/repo.gitgit@github.com:user/repo.git
Easiest setupgh auth login does it allMake a key, paste the public half into GitHub
Good forBeginners, locked-down networksDaily work, many repos

An SSH key comes in two halves. The private key stays on your computer forever, like a house key. The public key (the file ending in .pub) goes to GitHub, like a lock that only your key opens.

Commands

Install

sudo apt update && sudo apt install git     # Ubuntu / Debian
sudo dnf install git                         # Fedora
xcode-select --install                       # macOS (or: brew install git)

On Windows, download Git for Windows from git-scm.com and run the installer. It includes Git Bash, a terminal where every command in this course works.

Tell Git who you are

git config --global user.name "Your Name"
git config --global user.email "you@example.com"

Sets the name and email stamped on every commit you make on this computer.

git config --global init.defaultBranch main

New repos start on a branch called main, which matches GitHub.

git config --global core.editor "nano"         # or: "code --wait" for VS Code

The editor Git opens when it needs you to type a message. Without this, Git may open Vim, which confuses many beginners.

git config --global pull.rebase false

Makes git pull combine changes with a merge, which is what this course uses. Without it, newer Git versions stop and ask you to choose.

Check your settings

git config --list --show-origin     # every setting, and which file it came from
git config user.email               # the value Git will actually use here

Use the second form when you're unsure which level is winning.

Connect to GitHub

gh auth login

Easiest path. Uses the GitHub CLI: pick GitHub.com → HTTPS → "Yes" to authenticate Git, then log in through your browser. After that, git push just works.

ssh-keygen -t ed25519 -C "you@example.com"   # create a key pair (press Enter for defaults)
cat ~/.ssh/id_ed25519.pub                    # print the PUBLIC half, then copy it
ssh -T git@github.com                        # test the connection

The SSH path. Paste the printed public key into GitHub under Settings → SSH and GPG keys → New SSH key, then run the test.

Hands-on lab

These settings are real and stay on your computer. That's the point of this module.

  1. Check that Git is installed. If you get "command not found", run the install command for your system first. 
    git --version
git version 2.43.0

    A version of 2.28 or newer (needed for init.defaultBranch).

  2. Set your identity, default branch, editor and pull behavior. Use your own name and email. 
    git config --global user.name "Your Name"
git config --global user.email "you@example.com"
git config --global init.defaultBranch main
git config --global core.editor "nano"
git config --global pull.rebase false

    No output. Git only prints something when there is a problem.

  3. Read your settings back. 
    git config --global --list
user.name=Your Name
user.email=you@example.com
init.defaultbranch=main
core.editor=nano
pull.rebase=false

    Your five settings. Git shows setting names in lowercase, and that's fine.

  4. See the "closest wins" rule. Make a test repo and give it its own email. 
    mkdir -p ~/git-playground/m02 && cd ~/git-playground/m02
git init -q
git config user.email "work@company.com"      # no --global means local: this repo only
git config user.email
work@company.com
git config --global user.email
you@example.com

    Inside this repo Git uses the local email. Everywhere else it still uses your global one. (You'll learn git init properly in Module 03.)

  5. Connect to GitHub. Choose one path: run gh auth login, or create an SSH key and add it to GitHub as shown in Commands. Then test it. 
    gh auth status                 # if you used gh
ssh -T git@github.com          # if you used SSH
Hi your-username! You've successfully authenticated, but GitHub does not provide shell access.

    "Logged in to github.com" from gh, or the "Hi your-username!" line from SSH. The first SSH connection asks you to trust GitHub's fingerprint. Compare it with the fingerprints listed in GitHub's docs, then type yes.

At work

On your first day at a new job, you clone the company repo on your own laptop and push a fix. In the pull request your commit shows a grey, unknown avatar. Your global email is your personal Gmail, and the company's GitHub organization only knows your work email.

You fix it with a local setting inside the company repo: git config user.email "you@company.com". Your commits there now show your work identity, and your personal projects keep your personal email. Many developers also keep their company repos in one folder, such as ~/work, so this is easy to remember.

Common mistakes

Skipping user.name and user.email, then getting "Author identity unknown" on your first commit.

Run the two git config --global user.* commands once. The commit will work after that.

Typing your GitHub account password when git push asks for one, and getting "Support for password authentication was removed".

GitHub needs a token or an SSH key instead of your password. Run gh auth login once and it sets everything up.

Sharing the private key file (id_ed25519) instead of the public one.

Only ever copy the file ending in .pub. If a private key leaks, delete that key from GitHub right away and make a new pair.

A typo in a setting name, like git config --global user.mail …. Git saves it without any warning.

Check with git config --global --list. Remove the wrong one with git config --global --unset user.mail.

Quick quiz

Where does git config --global save your settings?

In ~/.gitconfig, a file in your home folder. Every repo you work on reads it.

A repo has a local user.email and you also have a global one. Which does Git use in that repo?

The local one. The closest level wins: local beats global, and global beats system.

Which SSH key file do you paste into GitHub?

The public key, the file ending in .pub (for example ~/.ssh/id_ed25519.pub). The private key never leaves your computer.

Summary

  • Install Git once per computer and check it with git --version.
  • Set user.name and user.email. They are stamped on every commit.
  • Settings live at three levels. Local beats global, and global beats system.
  • GitHub needs a token (gh auth login) or an SSH key to push. Never your password.
