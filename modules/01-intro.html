What is Git and GitHub

Understand what Git does, how it is different from GitHub, and the few words every developer uses every day.

Learning goals

  • Explain what version control is and why every team uses it
  • Tell the difference between Git and GitHub
  • Name the three places your work lives: working directory, staging area, repository
  • Know what a commit, a branch and main are
  • Check that Git is installed on your computer

The idea

You have probably seen files named report_final.docx, report_final_v2.docx and report_REAL_final.docx. That is version control done by hand, and it breaks fast. You forget which file is newest, and two people editing at once overwrite each other.

Version control is a system that records every change to your project, who made it, and why. You can go back to any earlier version at any time. It is a time machine for a folder.

Git: the tool on your computer

Git is a free program that runs on your computer. When you tell it to, Git takes a snapshot of your project. That snapshot is called a commit. Commits form a chain, so you can see the full history and return to any point. Git works completely offline.

GitHub: the website for sharing

GitHub is a website that stores copies of Git projects online. It adds tools for teams: pull requests, code review, issues, and free website hosting (this site runs on GitHub Pages). Think of Git as a camera that takes photos, and GitHub as the shared album where your team keeps them and comments on them.

The three places your work lives

A change does not go straight into history. It moves through three places, and you decide when it moves:

  Working directory      Staging area         Repository
  files you edit   ───►  next snapshot  ───►  saved history
                 git add             git commit

The working directory is your normal folder. The staging area is a waiting room where you pick which changes go into the next snapshot. The repository (or "repo") is the history Git has saved.

Branches and main

A branch is a separate line of work. You can try something new on a branch without touching the official version. When the work is ready, you merge it back. The official branch is usually called main.

main      A───B───C───────F
               \         /
feature         D───────E
                          F = merge commit: feature joins main

This page was written on a branch called module/01-intro and merged into main through a pull request. You'll see exactly how in the lab.

Commands

git --version

Shows which version of Git is installed. If you see "command not found", Git is not installed yet (Module 02 fixes that).

git status

Asks Git "what is going on in this folder?" You will run this more than any other command.

git help commit      # full manual for one command
git commit -h        # short summary of its options

Built-in help. Every Git command has a manual page, and it works offline.

Hands-on lab

Work in a scratch folder so experiments never touch a real project. Open a terminal.

  1. Check that Git is installed. 
    git --version
git version 2.43.0

    A line starting with git version. Any version 2.28 or newer is fine.

  2. Make a playground folder for this course and step into it. 
    mkdir -p ~/git-playground/m01
cd ~/git-playground/m01

    No output. That's normal for these commands.

  3. Ask Git about this folder. 
    git status
fatal: not a git repository (or any of the parent directories): .git

    An error, and that is the lesson. Git only tracks folders you have told it to track. You will do that with git init in Module 03.

  4. Look at a real Git history: this website's. Open the commits on main and find the very first one, chore: create project skeleton.

    A list of commits, each with a message, an author and a short ID like 81238f4.

  5. Now open the closed pull requests and open the one that added Module 01. Look at the Files changed tab.

    The exact lines that were added to create this page, reviewed before they reached main.

At work

Five developers work on the same website. Without Git, they email zip files around, and on Friday someone's changes silently overwrite someone else's.

With Git and GitHub, each developer works on their own branch on their own laptop. When a feature is ready, they push the branch to GitHub and open a pull request. A teammate reviews it, asks for one fix, then approves. The branch is merged into main, and the site deploys from main. If something breaks, the team can see exactly which commit caused it and undo just that commit.

Common mistakes

Thinking Git and GitHub are the same thing.

Git is the tool on your computer. GitHub is one website that hosts Git repos. You can use Git for years without ever touching GitHub.

Thinking Git saves your work automatically, like Google Docs.

Saving a file in your editor is not a commit. Git records history only when you run git commit.

Running Git commands in the wrong folder and getting "not a git repository".

Move into the project folder first with cd. Run pwd to check where you are.

Putting passwords or API keys in a repo that is pushed to a public GitHub repository.

Anyone can read a public repo, including its history. Keep secrets out of Git from day one. Module 12 shows how to use .gitignore for this.

Quick quiz

Can you use Git with no internet and no GitHub account?

Yes. Git runs entirely on your computer. You only need GitHub (or another host) to share your work with others.

Which three places does a change move through?

Working directory → staging area (with git add) → repository (with git commit).

What is main, and why does this website care about it?

main is the default, official branch. This site is published from main only, so a lesson appears online only after its branch is merged into main.

Summary

  • Version control records every change, so you can see history and go back.
  • Git is the tool on your computer. GitHub is a website for sharing and teamwork.
  • A change moves: working directory → staging area → repository.
  • A commit is a snapshot. A branch is a separate line of work. main is the official branch.
