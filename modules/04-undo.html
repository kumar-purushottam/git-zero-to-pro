Undo changes: restore, reset, revert

Made a mistake? Pick the right undo for where the mistake is right now: in your files, in staging, or in a commit.

Learning goals

  • Throw away edits you haven't staged with git restore
  • Unstage a file with git restore --staged
  • Fix your last commit with git commit --amend
  • Undo a commit safely with git revert, and know when git reset is dangerous

The idea

There is no single "undo" in Git. The right command depends on where the mistake is now, and on whether you have already pushed it.

The mistake is…UseOK after push?
An edit in a file, not stagedgit restore <file>(nothing was shared)
Staged by accidentgit restore --staged <file>(nothing was shared)
In your last commit, not pushedgit commit --amendNo: it replaces the commit
In a commit already pushedgit revert <id>Yes: it adds a new commit
In local commits you want gonegit reset HEAD~1No: it rewrites history
 
  before        A───B───C            main

  git revert C  A───B───C───C'       C' undoes C, history kept: safe
  git reset B   A───B                C removed: only before you push

git reset has three strengths. All of them undo the commit. They differ in what happens to your changes:

FlagStaging areaYour files
--softChanges stay stagedKept
--mixed (default)ClearedKept
--hardClearedThrown away

Commands

git restore notes.md

Throws away unstaged edits to a file and puts back the last saved version. Those edits are gone for good.

git restore --staged notes.md

Takes a file out of staging. Your edits stay in the file.

git commit --amend -m "docs: better message"   # fix the last message
git add forgotten.md
git commit --amend --no-edit                   # add a forgotten file to the last commit

Replaces your last commit with a corrected one. Only do this before pushing.

git revert a1b2c3d --no-edit

Makes a new commit that undoes commit a1b2c3d. History stays intact, so this is the safe choice for shared branches.

git reset --soft HEAD~1      # undo last commit, keep changes staged
git reset --hard HEAD~1      # undo last commit AND throw its changes away

HEAD~1 means "one commit before where I am". Use --hard only when you are sure.

Hands-on lab

Use each undo command once in a throwaway repo.

  1. Set up a repo with one commit. 
    mkdir -p ~/git-playground/m04 && cd ~/git-playground/m04
git init -q
echo "line one" > notes.md
git add notes.md && git commit -q -m "docs: add notes"

    No output (-q means quiet).

  2. Make a bad edit, then throw it away. 
    echo "oops" >> notes.md
git restore notes.md
cat notes.md
line one

    "oops" is gone.

  3. Stage something, then unstage it. 
    echo "line two" >> notes.md
git add notes.md
git restore --staged notes.md
git status -s
 M notes.md

    M: still edited, but no longer staged.

  4. Commit with a typo, then fix the message. 
    git add notes.md
git commit -q -m "docs: add line tow"
git commit -q --amend -m "docs: add line two"
git log --oneline
b7c8d9e (HEAD -> main) docs: add line two
a1b2c3d docs: add notes

    Still two commits. The typo commit was replaced, not added.

  5. Undo that commit the safe way. 
    git revert HEAD --no-edit
git log --oneline
f0e1d2c (HEAD -> main) Revert "docs: add line two"
b7c8d9e docs: add line two
a1b2c3d docs: add notes

    A third commit that undoes the second one. Nothing was erased.

At work

You merged a change to main that broke the checkout page, and three teammates have already pulled it. If you used git reset and force-pushed, their copies of main would no longer match GitHub's. Instead, you run git revert <id> and push. Everyone simply pulls the new "undo" commit, the site is fixed in minutes, and you fix the real bug calmly on a branch.

Common mistakes

Running git reset --hard with work you never committed. That work is lost.

Run git status first. If you want to keep the work, commit it or stash it (Module 11) before resetting.

Using --amend or reset on a commit you already pushed. Your history no longer matches GitHub's, and the next push is rejected.

Once a commit is pushed, undo it with git revert.

Running git restore <file> without checking first. It can't be undone.

Look at git diff <file> first, so you know exactly what you're throwing away.

Quick quiz

Your last commit message has a typo and you haven't pushed. What's the quickest fix?

git commit --amend -m "the right message"

A bad commit is already on GitHub's main and teammates have pulled it. Which command?

git revert <id>. It adds an undo commit instead of rewriting history that others already have.

What does git reset --soft HEAD~1 keep?

All the changes from that commit, still staged. Only the commit itself is undone.

Summary

  • Unstaged edit: git restore. Staged by accident: git restore --staged.
  • Last commit, not pushed: git commit --amend.
  • Already pushed: git revert. It's safe because it adds a commit.
  • git reset rewrites history. --hard also throws changes away.
