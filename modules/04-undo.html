Undo changes: restore, reset, revert

Made a mistake? Pick the right undo for where the mistake is right now: in your files, in staging, or in a commit.

Learning goals

  • Throw away edits you haven't staged with git restore
  • Unstage a file with git restore --staged
  • Fix your last commit with git commit --amend
  • Undo a commit safely with git revert, and know when git reset is dangerous

The idea

There is no single "undo" in Git. The right command depends on where the mistake is now, and on whether you have already pushed it.

The mistake is…UseOK after push?
An edit in a file, not stagedgit restore <file>(nothing was shared)
Staged by accidentgit restore --staged <file>(nothing was shared)
In your last commit, not pushedgit commit --amendNo: it replaces the commit
In a commit already pushedgit revert <id>Yes: it adds a new commit
In local commits you want gonegit reset HEAD~1No: it rewrites history
 
  before        A───B───C            main

  git revert C  A───B───C───C'       C' undoes C, history kept: safe
  git reset B   A───B                C removed: only before you push

git reset has three strengths. All of them undo the commit. They differ in what happens to your changes:

FlagStaging areaYour files
--softChanges stay stagedKept
--mixed (default)ClearedKept
--hardClearedThrown away

Commands

git restore notes.md

Throws away unstaged edits to a file and puts back the last saved version. Those edits are gone for good.

git restore --staged notes.md

Takes a file out of staging. Your edits stay in the file.

git commit --amend -m "docs: better message"   # fix the last message
git add forgotten.md
git commit --amend --no-edit                   # add a forgotten file to the last commit

Replaces your last commit with a corrected one. Only do this before pushing.

git revert a1b2c3d --no-edit

Makes a new commit that undoes commit a1b2c3d. History stays intact, so this is the safe choice for shared branches.

git reset --soft HEAD~1      # undo last commit, keep changes staged
git reset --hard HEAD~1      # undo last commit AND throw its changes away

HEAD~1 means "one commit before where I am". Use --hard only when you are sure.
